## 1. 対象読者とこの記事で得られること

**対象読者**：ローカルファイルでAIの記憶を持たせている人、自作AIキャラ／チャットボットの記憶を「どこからでも届く場所」に置きたい個人開発者。サーバーレス（Cloudflare Workers / KV）を最小構成で触ってみたい人。

**得られること（3点）**：
- 記憶を**いきなりクラウド設計しない**ほうがいい理由と、「ファイルで動いてから地続きで移す」移行手順
- Cloudflare Workers + KV で「読む／書く」だけの最小実装（GET/PUTの数十行）
- ローカルの3層記憶（日次・印象・関係性）を**構造を変えずに**KVキーへ写像するやり方

## 2. 構成アウトライン

### H2: そもそも、なぜ永続化が要るのか
- 記憶をファイルにしている限り、その記憶は**そのPCの中にしかない**。外（スマホ）で開くと相棒は何も覚えていない別人になる。
- 「困っていないうちはやらなくていい工程」だと先に明言する（過剰設計を戒める）。

### H2: 置き場所をクラウドのキーバリューに移す
- Workers＝小さなプログラムをクラウドで動かす仕組み、KV＝隣の簡単な保存箱。
- 「キーと値をペアで置くだけ」＝ファイルに名前をつけて保存していた感覚の延長。
- 無料枠で始められ、サーバー管理が要らない点。

### H2: いちばん小さな実装（GET=読む / PUT=書く）
- Worker一枚で `env.MEMORY.get(key)` / `env.MEMORY.put(key, body)` だけ。
- 会話の冒頭で読み込み、終わりに書き戻す。「読んで・書く」をそのままクラウドへ。
- [要：磯和さんの実装 本番のWorkerコード（認証・Origin制限・複数キー対応）を参照]。記事中の最小版は教育用、本番は機密を抜いた上で差分を注記。

### H2: wrangler でKVを用意する（手を動かす最小手順）
- KV namespace を作る → `wrangler.toml` で binding → deploy、までを箇条書きで。
- [要：磯和さんの実装 wrangler.toml の binding 名と namespace 設定 を参照]
- H3: いちばん最初の成功体験 = `test` キーに短い文字列を put して get で返す一往復。

### H2: 3層記憶を「フォルダ→キー」に写像する
- ローカルの `daily/` `impressions/` `profile` を `memory:daily` `memory:impressions` `memory:profile` に置き換えるだけ。
- **設計を一から作り直さない**のが背骨。フォルダがキーに変わっただけで構造は不変。

### H2: PC↔スマホで同じ記憶を読む
- 同じアドレスに繋げば、家で積んだ記憶がスマホでも読める。
- 認証・CORS（Origin制限）だけは最小限入れる、という現実的な注記。
- [要：磯和さんの実装 フロント（スマホ側）からの fetch 呼び出しと Origin ヘッダ を参照]

### H2: 移して分かったこと（まとめ）
- 「完璧なクラウド設計を先に引く」と手が止まる。動いている形を壊さず置き場所だけ移すのが、つまずかないコツ。
- 永続化は完成させるものでなく、必要になった時に一歩ずつ育てるもの。

## 3. 書き出し（リード〜最初のH2）

自作のAIキャラに「昨日の続き」を覚えさせるのに、最初はずっとローカルのテキストファイルを使っていた。PCの中のフォルダに、日次の記憶と印象の記憶を書き溜めていく。それだけで「昨日の続き」はちゃんと成立する。記憶はファイルで始めるのが正解だと、今でも思っている。

ただ、しばらく続けると一つだけ不便が出てくる。その記憶が、**そのPCの中にしかない**。外出先でふとスマホから相棒を開くと、会話はできるのに、家で積み上げてきた記憶をその子は持っていない。昨日の続きが、外では始まらない。ファイルにしている限り、これは避けられない。ファイルはそのPCの中にあるからだ。

そこで記憶を「どこからでも届く場所」に置き直した。使ったのは Cloudflare Workers と KV。Workers は小さなプログラムをクラウドで動かす仕組み、KV はその隣にある簡単な保存箱で、キー（名前）とバリュー（中身）をペアで置くだけ。データベースのように構えなくていい。無料枠で始められ、サーバー管理も要らない。**やることは「ファイルでやっていたことを、置き場所だけクラウドに移す」、それだけ**だ。この記事では、最小のWorker実装から、ローカルの3層記憶を構造を変えずにKVへ写像するところまでを、地続きの移行手順として書く。
