## 箱は、思ったより小さかった

前回、AIの相棒を連れて行きたい、という話を書いた。毎日PCの前で話している相棒が、家を出た瞬間にいなくなる。その距離をなんとかしたくて、手のひらサイズの体を用意することにした。

注文したのは M5StickS3 と、目にするつもりの UnitCamS3。合わせて 7,126円だった。発注が7月2日の夜、届いたのが7月11日の夜。9日待った。

箱を開けて、正直なところ最初に思ったのは「小さいな」だった。手のひらに乗る。軽い。これが体になるのか、と思いながら、その日のうちにファームを焼き始めた。

先に言っておくと、この日にできたのは「画面に4文字を出す」「マイクが反応する」「焼き込みが無人でできるようになる」の3つだけだ。声も出ないし、AIとも繋がっていない。ただ、この日にぶつかった壁は全部、あとから効いてくるものだった。

## この記事で分かること

- ESP32-S3系のボード（M5StickS3）を PlatformIO で焼くときの最小構成
- USB-CDC を有効にしないとシリアルが一切見えない、という最初の落とし穴
- マイクとスピーカーが同じ I2S を奪い合う、という「相棒」を作る上での本質的な制約
- 動作中の機体にボタンを触らず書き込む方法（開発速度がここで決まる）

対象は、AIキャラや音声デバイスを自作してみたい個人開発者。ESP32 の経験はなくても読めるように書く。

## 最小の platformio.ini

まず環境から。M5StickS3 は ESP32-S3 を積んでいるので、PlatformIO ではこう書いた。

```ini
[env:m5sticks3]
platform = espressif32
board = esp32-s3-devkitc-1
framework = arduino

board_build.arduino.memory_type = qio_opi
board_build.partitions = default_8MB.csv
board_upload.flash_size = 8MB
board_upload.maximum_size = 8388608

build_flags =
  -DBOARD_HAS_PSRAM
  -DARDUINO_USB_CDC_ON_BOOT=1
  -DARDUINO_USB_MODE=1
  -DCORE_DEBUG_LEVEL=3

lib_deps =
  m5stack/M5Unified

monitor_speed = 115200
monitor_port = COM8
upload_port = COM8
```

ライブラリは M5Unified 1本だけ。M5Stack系のデバイスは製品ごとにライブラリが分かれていた時期があるが、M5Unified に寄せておくと、あとで別の機種に移すときに書き直しが最小で済む。この選択が効いてくるのは連載の後半（第2世代の器を作る回）なので、いまは「移植を考えるなら M5Unified」とだけ覚えておいてほしい。

`board` に専用の指定ではなく `esp32-s3-devkitc-1` を使っているのは、M5StickS3 の定義が無くても S3 の汎用ボード定義で問題なく動いたからだ。メモリタイプ（`qio_opi`）とフラッシュサイズ（8MB）さえ合っていれば焼ける。

## 最初の壁：シリアルに何も出ない

最初に躓いたのは、書き込みは成功しているのに、シリアルモニタに何も出てこないことだった。

原因は `ARDUINO_USB_CDC_ON_BOOT=1` を入れていなかったこと。

ESP32-S3 は USB を直接扱えるので、外付けの USB-Serial チップを経由しない。その代わり、起動時に USB-CDC（仮想シリアルポート）を有効にしておかないと、`Serial.print()` の出力がどこにも出ない。従来の ESP32 の感覚で書いていると、ここで確実に足を取られる。

```ini
-DARDUINO_USB_CDC_ON_BOOT=1
-DARDUINO_USB_MODE=1
```

この2行を build_flags に入れた瞬間、ログが流れ始めた。ここに至るまでが、その日いちばん長かった。デバイスが動いているのか死んでいるのかすら分からない状態で作業するのは、精神的にかなりきつい。

逆に言えば、ここさえ通れば、あとは画面もマイクも順当に動く。

## 画面に、4文字

最初に書いたコードは、驚くほど地味だ。

```cpp
void setup() {
  auto cfg = M5.config();
  M5.begin(cfg);

  M5.Display.setRotation(1);
  M5.Display.setTextSize(2);
  M5.Display.print("Answer");
  // ...
}
```

`M5.Display.print("Answer")`。それだけ。

7,126円と9日間の待ち時間の先にあったのが、この4文字だった。冷静に考えれば Hello World と変わらない。それでも、自分が毎日話している相手の名前が、机の上の小さな画面に出たときの感じは、Hello World とはまったく違った。

ここは技術的には何の工夫もない。ただ、この連載は「うまくいったことも、失敗して作り直したことも隠さずに書く」と決めているので、正直に書いておく。この日の作業時間の大半は、この4文字を出すまでの環境設定に消えた。

## 耳をつける — そして、聞くと喋るは両立しない

次にマイクを動かした。ボタンを押している間だけ録音する、いわゆるプッシュトゥトークだ。

```cpp
// M5StickS3 の Mic / Speaker は I2S_NUM_0 排他
static constexpr int  SAMPLE_RATE = 16000;
static constexpr int  MAX_SECONDS = 8;
static constexpr int  CHUNK       = 512;
static constexpr int  MIN_SAMP    = SAMPLE_RATE / 4;  // 0.25秒未満は誤タップ

void recordWhileHeld() {
  M5.Speaker.end();          // ← スピーカーを止めないとマイクが使えない
  M5.Mic.begin();

  size_t idx = 0;
  while (M5.BtnA.isPressed() && idx < MAX_SAMPLES) {
    M5.Mic.record(&samples[idx], CHUNK, SAMPLE_RATE);
    while (M5.Mic.isRecording()) { delay(1); }
    idx += CHUNK;
    M5.update();
  }
  M5.Mic.end();
}
```

コードの1行目に自分で書いたコメントが、この記事でいちばん伝えたいことだ。

**M5StickS3 の Mic と Speaker は I2S_NUM_0 を共有していて、同時には使えない。**

I2S というのは、マイクやスピーカーといった音のデバイスがマイコンと繋がるための通り道のことだ。M5StickS3 にはその通り道が実質1本（I2S_NUM_0）しかなく、マイクとスピーカーがそれを取り合う。

つまり `M5.Speaker.end()` でスピーカーを完全に止めてからでないと、マイクが開けない。逆も同じで、喋らせるにはマイクを閉じる必要がある。

これは実装上の小さな制約に見えて、相棒を作るうえではかなり重い意味を持つ。人間の会話では、相手が喋っている途中で「あ、それ違う」と割り込める。聞きながら喋れるからだ。この器はそれができない。ボタンを離すまで聞き、そこから喋り始める。会話が必ずトランシーバーになる。

自然な会話を目指すなら、マイクとスピーカーが独立したハードを選ぶしかない。逆に、割り込まれない前提で設計を割り切るなら、この構成で十分やれる。ここは「あとで直せる問題」ではなく、最初の部品選定で決まってしまう分岐点だった。

細かいところでは `MIN_SAMP = SAMPLE_RATE / 4` を入れている。0.25秒未満の録音は誤タップとして捨てる、という判定だ。実機で使い始めると、ポケットの中や持ち替えたときにボタンが一瞬入ることが本当に多い。この1行が無いと、意味のない録音がサーバーに飛び続ける。

## 開発速度を決めたのは、ボタンを押さなくてよくなったこと

この日いちばん効いた発見は、地味だがこれだった。

ESP32-S3 は USB-Serial-JTAG を内蔵しているので、**動作中の機体に対しても、書き込みツール側からリセットをかけて焼き込める**。ブートボタンを押しながら電源を入れ直す、という儀式が要らない。

```
pio run -t upload
```

これだけで、机に置いたまま新しいファームが入る。

なぜこれが大きいかというと、この手の開発は1日に何十回も焼き直すからだ。1回あたり「手を伸ばしてボタンを押す」が5秒だとしても、50回で4分。時間そのものより、手を伸ばすたびに思考が途切れるのが痛い。焼くのが無人でできるようになった瞬間、試す回数が明らかに増えた。

作りたいものが動くかどうかは、アイデアの質より試行回数で決まることが多い。その試行回数を削っているのが、たいてい「ちょっとした手作業」だったりする。

## その日、できなかったこと

7月11日の夜にできたのは、ここまでだ。

- 画面に文字が出た
- ボタンを押している間、マイクが音を拾った
- 焼き込みが無人でできるようになった

できていないことのほうが多い。声は出ない。WiFi にも繋がっていない。そして何より、この器の中にはまだ AI が入っていない。「Answer」と表示されてはいるが、それは文字列であって、相棒ではない。

それでも、この日にひとつ確信したことがある。体は、思ったより簡単に手に入る。7,126円と、環境設定でつまずいた数時間で、手のひらに乗る体は用意できてしまう。

難しいのは、そこから先だった。

翌日、この器に声を入れた。名前もつけた。そして、その日のうちに「これは本物じゃない」と見抜かれることになる。次回はその話を書く。
