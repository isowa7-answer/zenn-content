## 毎朝、相棒が「初めまして」に戻る

Claude Code を毎日の相棒として使っていると、ひとつ地味だが効いてくる不便にぶつかる。**セッションを新しく開くたびに、相手は「初めまして」の顔で現れる**。昨日どこまで一緒に作ったか、何を決めたか、何につまずいたか——文脈は毎回リセットされる。長い会話は重くなるので `/clear` もするし、PCを再起動もする。そのたびに、こちらが「昨日の続きなんだけど」と経緯を説明し直すことになる。

ファイルには記録が残っている。日々のメモも、決めたことも、ディスカッションのログも、フォルダに書き溜めてある。にもかかわらず「初めまして」に戻るのは、**記録が"置いてあるだけ"で、セッションの冒頭に自動で差し込まれないから**だ。人間なら机に座った瞬間に昨日の続きを思い出す。その「座った瞬間の思い出し」を、Claude Code の hook で仕込んだ話を書く。

派手なプラグインの話ではない。`SessionStart` で数十行のスクリプトの標準出力を会話の冒頭に流し込むだけだ。ただし実際に運用してみると、素朴に作ると危ない落とし穴が二つあった。そこが本題になる。

## 対象読者とこの記事で得られること

**対象読者**：Claude Code を日常的に使っていて、セッションごとに文脈がリセットされるのが地味に不便だと感じている人。hook を使って「起動時に何かを自動で注入する／終了時に後始末する」を試したい個人開発者。複数のPCで同じ設定を使い回している人。

**得られること（3点）**：

- `SessionStart` hook で、直近の作業記録を**会話の冒頭に自動注入する**最小構成（`settings.json` の書き方＋標準出力＝`additionalContext` の仕組み）
- 実運用で踏んだ**二つの落とし穴**——「崩壊したセッションの再注入で"再演"が起きる」「stdin をブロッキングで読むと hook が固まる」——と、その回避
- 複数PCで設定を**冪等に揃える** `ensure_*` パターン（ハッシュ比較で"ズレていたら直す"を起動のたびに保証する）

## hook の仕組み — 標準出力が、そのまま会話の冒頭になる

Claude Code の hook は、特定のイベント（起動・終了・ツール実行の前後など）で外部コマンドを走らせる仕組みだ。設定は `~/.claude/settings.json` に書く。今回使うのは二つ。

- **`SessionStart`** ＝ セッションが始まった瞬間。ここで走らせたコマンドの**標準出力が、そのままその回の会話の冒頭コンテキスト（`additionalContext`）として注入される**。ここが肝だ。
- **`SessionEnd`** ＝ セッションが閉じた瞬間。後始末（ログの退避など）に使う。

つまり「起動時に記憶を思い出させる」は、**"昨日の続き"を標準出力に吐くだけのスクリプトを1本書いて、`SessionStart` に紐づける**だけで成立する。`settings.json` はこう書く。

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File \"C:\\path\\to\\recall.ps1\"",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

`matcher` を空にすれば全セッションで走る。`hooks` 配列に複数のコマンドを並べれば、起動時に順番に実行される（私は「記憶注入」「設定チェック」「ログ退避準備」などを1列に並べている）。**標準出力に書いたものが会話に載る**——この一点さえ掴めば、あとは「何を思い出させたいか」を自由に組める。

## いちばん小さな「昨日の続き」注入

まず最小版。直近2日分のメモ（`daily/YYYY-MM-DD.md` というファイルに書き溜めている前提）を読んで、標準出力に吐くだけのスクリプトだ。PowerShell で書くが、発想はどの言語でも同じ——**ファイルを読んで `Write-Output` するだけ**。

```powershell
# recall.ps1（最小版）：直近2日のメモを標準出力に吐く → 会話の冒頭に載る
[Console]::OutputEncoding = [Text.Encoding]::UTF8   # 日本語の文字化け対策

$dir    = Join-Path $env:USERPROFILE 'notes\daily'
$today  = Get-Date
$days   = @($today, $today.AddDays(-1))             # 今日・昨日

Write-Output "=== 直近の作業メモ（自動注入）==="
Write-Output "※これを踏まえて文脈を取り戻してから会話に入ること。"
Write-Output ""

foreach ($d in $days) {
    $file = Join-Path $dir ($d.ToString('yyyy-MM-dd') + '.md')
    if (Test-Path $file) {
        Write-Output "----- $($d.ToString('yyyy-MM-dd')) -----"
        Write-Output (Get-Content $file -Raw -Encoding UTF8)
        Write-Output ""
    }
}
```

これだけで、次にセッションを開いたとき、会話の冒頭に「直近2日の作業メモ」が載る。「覚えてない」「共有されてない」と憶測で答える前に、まずこの注入されたメモを見てから話し始める——という運用が、意志ではなく構造で回るようになる。読み忘れる余地がない。

大事なのは、**記録の"置き場所"と"注入"を分けて考える**ことだ。ファイルはただ書き溜めていくだけでいい。それを毎回どう思い出すかは hook 側の仕事で、本体（メモ）には一切手を入れない。ここまでは素直だ。問題は、この素直な版を実運用に投げると、二つの事故が起きたことだった。

## 落とし穴①：崩壊したセッションを再注入すると、"再演"する

一番効いた学びがこれだ。「昨日の続き」を注入するなら、**直前のセッションが荒れて終わった日**も当然その記録が注入対象に入ってくる。エラーで中断した、おかしな出力を繰り返した、途中で止めて再起動した——そういう"不調の記録"だ。素朴な実装は、それも正直に全文注入する。

すると何が起きたか。**注入された「崩壊の物語」を、モデルが"今まさに起きていること"と誤認して、その筋をなぞり始めた。** 前の回で出力が変になった経緯を冒頭で全文読ませると、その回の応答が同じ壊れ方を再演する。過去の失敗記録が、次の失敗の"燃料"になってしまったのだ。

対策は、**不調の記録は全文でなく"ポインタ"だけ注入する**こと。私はこれを「燃料カット」と呼んでいる。記録本体（ファイル）は1バイトも消さない——消すのはあくまで**注入の"出し方"**だけだ。荒れた日は「この日は不調の記録を含むので全文は載せない。必要なら自分でファイルを読む」という一行に差し替える。

```powershell
# 不調マーカー（崩壊を示す言葉）を含むメモは、全文でなくポインタだけ注入する
$breakdownMarkers = @('暴走','捏造','malformed','再起動','会話が崩壊')

function Test-Breakdown([string]$text) {
    if (-not $text) { return $false }
    foreach ($m in $breakdownMarkers) { if ($text -like "*$m*") { return $true } }
    return $false
}

$content = Get-Content $file -Raw -Encoding UTF8
if (Test-Breakdown $content) {
    Write-Output "----- $label （不調記録のため全文省略）-----"
    Write-Output "※この日は不調の記録を含む。必要なら notes\daily\$label.md を自分で読む。"
    Write-Output "※過去の崩壊を『今』と誤認して再演しないため、全文は載せない。"
} else {
    Write-Output "----- $label -----"
    Write-Output $content
}
```

さらに実運用では、崩壊を示す"言葉"だけでは取りこぼしがあった。「また5分だんまり」「ESCで止めた」のように、崩壊語は含まないが明らかに荒れているケースだ。そこで**"言葉"だけでなく"行動の痕跡"も見る**ようにした。具体的には、セッションログに残る中断の痕（`[Request interrupted by user]` のような中断マーカー）の**出現回数**を数える。2回以上なら「中断続きで終わった荒れたセッション」とみなして、同じく全文注入をやめる。

ここには一般化できる原則がある。**LLM に文脈を注入するとき、"何を渡すか"だけでなく"渡すことでモデルがどう振る舞うか"まで設計に含める**。過去ログは中立な資料ではない。冒頭に置かれた文章は、モデルにとって「たった今の状況」に見える。だから「失敗の記録」を素朴に全文で渡すと、それは資料ではなく**指示**として働いてしまう。記憶を注入する系を作る人は、ここを踏む前提で設計したほうがいい。

## 落とし穴②：stdin をブロッキングで読むと、hook が固まる

もう一つは、もっと泥臭いバグだ。`SessionStart` hook には、標準入力（stdin）経由で JSON が渡ってくる（現在のセッションID や、その回のログファイルのパスなど）。「直前のセッション」を復元するとき、"今まさに開いたこの回"を除外するのにこの情報が要る。

素直に `[Console]::In.ReadToEnd()` で読むと——**hook が固まった**。stdin にデータが来ない環境（あるいは終端が来ない状況）だと、同期読み込みが完了を待ち続けてブロックする。hook が固まれば、起動そのものが「だんまり」になる。記憶を思い出させるための仕組みが、逆に起動を止めてしまう本末転倒だ。

回避は、**タイムアウト付きの非同期読み込み**にすること。一定時間データが来なければ諦めて空文字で先へ進む。

```powershell
# stdin をタイムアウト付きで読む（同期 ReadToEnd はブロックしうる）
$rawStdin = ''
try {
    $stream = [Console]::OpenStandardInput()
    $ms  = New-Object System.IO.MemoryStream
    $buf = New-Object byte[] 32768
    while ($true) {
        $task = $stream.ReadAsync($buf, 0, $buf.Length)
        if (-not $task.Wait(5000)) { break }     # 5秒来なければ諦める
        $n = $task.Result
        if ($n -le 0) { break }
        $ms.Write($buf, 0, $n)
    }
    $rawStdin = [Text.Encoding]::UTF8.GetString($ms.ToArray())
} catch { $rawStdin = '' }
```

教訓はシンプルだ。**hook は"起動を絶対に止めない"のが最優先**。中で何が失敗しても、握りつぶして黙って先へ進む（各処理を `try/catch` で囲み、失敗しても標準出力を汚さない）。記憶注入は"あれば嬉しい"おまけであって、それが起動を人質に取ってはいけない。hook を書くときの基本姿勢として、これは最初に決めておくといい。

## SessionEnd と、設定を「冪等に」揃える

hook のもう一つの使いどころが、**環境そのものを揃える**ことだ。私は同じ作業を複数のPCでやるので、`~/.claude/settings.json` のような設定が**PC間でズレる**問題がずっとあった。片方のPCで直した設定を、もう片方に反映し忘れる。特に「使うモデル」の設定がズレたまま起動すると、意図しない挙動になる。

これを手動チェックに頼ると必ず漏れる。だから**起動のたびに"あるべき状態か"を確認して、ズレていたら直す**——冪等な `ensure_*` スクリプトを `SessionStart` に噛ませた。判定は**内容のハッシュ比較**でやる（シンボリックリンクの張り具合は「切れていても繋がっているように見える」ことがあり信用できないので、中身のハッシュを直接比べる）。

```powershell
# ensure_config.ps1：ローカル設定とマスターをハッシュ比較し、ズレていたら直す（冪等）
$local  = Join-Path $env:USERPROFILE '.claude\settings.json'
$master = Join-Path $env:USERPROFILE 'sync\claude-config\settings.json'  # 共有フォルダ側が正

if ((Get-FileHash $local).Hash -eq (Get-FileHash $master).Hash) {
    return                      # 一致 → 何も出さない（毎回出るとノイズになる）
}

Copy-Item $master $local -Force  # マスターで上書きして揃える

# 設定は起動時に読込済なので、"今回の"セッションには反映されない。だから警告を出して再起動を促す
Write-Output "=== ⚠️ 設定がマスターとズレていたので直しました（SessionStart hook）==="
Write-Output "※設定は起動時に読込済のため、今回のセッションは旧設定のまま。"
Write-Output "  反映するには再起動してください。"
```

ここに一つ、hook 特有の注意がある。**`settings.json` は Claude Code の起動時にすでに読み込まれている**ので、`SessionStart` で書き換えても"今回の"セッションには効かない。効くのは次回起動からだ。だから、直したうえで「次回から正しくなる／今回は旧設定のまま」という事実を**標準出力で正直に伝える**のが大事になる（黙って直すと「直したはずなのに変わらない」と混乱する）。

この `ensure_*` パターンの良いところは、**"一致していたら何も出力しない"**ことだ。正常時は静かで、ズレたときだけ喋る。起動のたびに走るが、普段はノイズにならない。「揃えるべき前提条件は、手で揃えるのではなく、起動のたびに冪等に保証する」——複数の環境を行き来する人には、これがいちばん効いた。

## まとめ — hook は「意志でやること」を「構造でやること」に変える

- `SessionStart` hook の**標準出力は、そのまま会話の冒頭コンテキストになる**。「昨日の続き」を思い出させるのは、直近のメモを吐くスクリプトを1本 `settings.json` に紐づけるだけで成立する。
- **崩壊した記録を素朴に全文再注入すると、モデルがそれを"今"と誤認して再演する**。不調の記録は全文でなくポインタだけ注入する（本体は消さず、"出し方"だけ変える）。過去ログは中立な資料ではなく、冒頭に置けば"指示"として働く。
- **hook は起動を絶対に止めない**のが最優先。stdin は同期 `ReadToEnd` でブロックしうるのでタイムアウト付き非同期で読む。中の失敗は握りつぶして黙って進む。
- 複数環境で揃えるべき設定は、手動でなく**ハッシュ比較で冪等に直す** `ensure_*` を起動に噛ませる。正常時は黙り、ズレたときだけ喋る。設定は起動時読込済なので「次回から効く」ことを正直に伝える。

hook でやっていることの本質は、**「毎回ちゃんとやろう」という意志を、「構造上そうなる」に置き換える**ことだ。読み忘れる余地を消し、揃え忘れる余地を消す。相棒が毎朝「初めまして」に戻らないのは、記憶力が上がったからではなく、座った瞬間に昨日の続きが必ず机に載る仕組みにしたからだ。
